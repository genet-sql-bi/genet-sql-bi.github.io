SQL Server · Medallion Architecture

Sales Data Warehouse & Analytics

An end-to-end sales analytics platform: a SQL Server data warehouse (bronze, silver, gold) loaded nightly from ERP and CRM source systems, a star schema with full product history, analytical SQL and a three-page Power BI dashboard.

Keeping product history (SCD Type 2) changed the margin story: in 2012 the true margin was 42.0%, not the 35.2% you get by costing every past sale at today's price.

Customers · RFM

Repeat customers drive revenue

Customers who ordered more than once are 37% of the base but bring in 77% of revenue. The At Risk group is 11% of customers and 27% of revenue, so that's where I'd focus retention first.

Method

Fixing RFM frequency scoring

63% of customers ordered once, so NTILE split identical customers into different groups at random. I switched to fixed thresholds (1, 2, 3+ orders), which made the segments much cleaner.

Business

From bike shop to broader retailer

Accessories and Clothing first appear in late 2012. Sales nearly tripled in 2013 ($5.8M to $16.3M), with bikes still about 94% of revenue.

Engineering decisions

03 / RELIABILITY
History

SCD Type 2 for products

Every product version is kept with a validity range, and each sale joins to the version valid on its order date. A quality check confirms every sale matches exactly one version.

Safety

One transaction per layer

Each load runs with SET XACT_ABORT ON, so a failure rolls the whole layer back. Tested by forcing a failure: every table kept its previous rows.

Quality gate

Fail on empty loads

An empty source file loads 0 rows without any error, so each table checks its row count and treats 0 as a failure.

Observability

Log to a table and re-throw

etl.load_log keeps rows, duration, status and errors. Failures are logged after rollback and re-thrown so the Agent job stops.

Design

Gold as views

Views keep gold in sync with silver at this size. At larger volumes I'd materialize gold as indexed tables with stable surrogate keys.

Data

Flag, don't delete

15 customers born before 1924 are flagged for source review, not removed. Only impossible future birthdates are set to NULL.
